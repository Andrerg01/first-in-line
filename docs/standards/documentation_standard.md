# Documentation Standard

## Documentation Layers

1. Project-level docs in docs/project_plan/
2. Engineering standards in docs/standards/
3. Feature docs close to owning code module

## Required Updates

When behavior changes, update:
- relevant README section
- affected feature documentation
- API contract docs if endpoint/schema changed

## File Template for Feature Docs

Each feature doc should include:
- purpose
- scope and non-scope
- inputs/outputs
- dependencies
- failure modes
- test notes

## Organization Rules

- Prefer short files by topic.
- Keep headings predictable.
- Add links from docs/standards/README.md when adding new standards.
